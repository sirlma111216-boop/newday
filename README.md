# 업무달력

한국어 개인 업무 일정관리 프로토타입입니다. Firebase 설정 전에는 로그인 없이 브라우저에 저장합니다. Firebase 설정 후에는 Google 로그인으로 본인의 PC와 휴대전화에서 같은 일정을 공유합니다. 정적 웹사이트 호스팅은 Cloudflare Pages를 사용할 수 있습니다.

Cloudflare Pages 배포, 보유 도메인 연결, Firebase 도입 설정은 [배포와 Firebase 안내](DEPLOYMENT.md)를 참고하세요. Firebase Google 로그인과 Firestore 동기화 코드를 포함합니다. 환경 변수 네 개를 설정하면 클라우드 모드가 활성화됩니다. 실제 프로젝트 설정과 보안 규칙 적용은 별도로 필요합니다.

## 디자인

첨부된 `DESIGN-clay.md`를 바탕으로 크림색 캔버스, 검정 주요 버튼, 청록 업무 카드, 라벤더·피치·민트·오커 분류, 분홍 마감 표시를 적용했습니다. 버튼·입력란은 12px, 일반 카드는 16px, 공통 업무 카드는 24px 모서리를 사용하며 그림자는 최소화했습니다.

`src/clay.css`에 디자인 토큰과 화면별 테마를 모았습니다. 기존 달력 구조와 기능은 유지합니다. 큰 소개 화면과 장식용 삽화는 추가하지 않았습니다. Plain Black은 제공되지 않은 전용 글꼴이므로 사용하지 않았고, Inter가 없으면 한국어 시스템 글꼴로 표시됩니다.

## 실행

GitHub에서 받은 소스는 먼저 아래 명령으로 설치·빌드한 뒤 **http://127.0.0.1:5173/** 을 여세요. 검증 및 Cloudflare 빌드 기준 Node.js 버전은 `.node-version`의 **24.19.0**입니다.

```sh
npm ci
npm run build
npm start
```

빌드 후에는 **실행.cmd**를 더블클릭하거나 `npm start`로 다시 실행할 수 있습니다. 별도로 제공한 완성본 ZIP에는 `dist`가 포함되어 설치·빌드를 생략할 수 있습니다. GitHub에는 소스와 잠금 파일을 저장하고 `dist`와 `node_modules`는 제외합니다. 창을 닫거나 Ctrl+C를 누르면 서버가 종료됩니다. 5173 포트가 사용 중이면 기존 미리보기를 사용하거나 기존 서버를 종료해 주세요.

브라우저 데이터는 **주소·포트·브라우저 프로필**별로 구분됩니다. 항상 `http://127.0.0.1:5173/`을 사용하세요. `localhost`나 다른 포트로 접속하면 별도의 저장 공간이 열립니다. `dist/index.html`을 파일로 직접 열지 마세요.

## 사용

- 날짜를 누르거나 **일정 추가**를 눌러 제목과 날짜만 입력해 저장합니다.
- **추가 옵션**에서 시간, 분류, 업무 연결, 메모, 링크, 체크리스트와 여러 알림을 설정합니다. 단순 일정도 한 번에 저장되며 별도 업무 생성 절차를 요구하지 않습니다.
- 기간은 입력한 종료일까지 포함됩니다. PC에서 막대를 끌어 이동하고, 마지막 끝의 `⋮`를 끌어 종료일을 변경합니다. 상세의 **수정**에서도 날짜를 바꿀 수 있습니다. 휴대전화에서는 목록과 날짜 입력 편집을 권장합니다.
- 같은 업무에 연결된 일정은 메모·자료·준비 사항·상태를 공유합니다. **이 업무에 일정 추가**로 접수·마감·발표를 이어서 등록합니다.
- **업무 완료**는 같은 업무의 일정 전체에 적용됩니다. 개별 일정 삭제와 업무 전체 삭제는 구분해 확인합니다.
- 왼쪽 분류, 미완료 필터와 상단 검색은 함께 동작합니다. 검색은 현재 표시 중인 달에서 확인하며 업무명·메모·체크리스트·링크 표시 이름도 검색합니다.
- **백업 및 가져오기**에서 JSON 파일을 내려받습니다. 가져오기는 건수 확인 후 현재 데이터를 전체 교체하며 병합하지 않습니다.

## 알림과 원노트

시간은 Asia/Seoul로 처리합니다. 종일 시작 알림은 09:00, 종일 종료/마감 알림은 23:59 기준입니다. 7일 전·1일 전·1시간 전·정각을 복수 선택할 수 있습니다. 저장 시 이미 지난 알림 시각은 새로 발송하지 않습니다.

앱 실행 중 2초 간격과 창 활성화 때 도래한 알림을 확인합니다. 앱을 다시 열면 저장 이후 놓친 알림을 수집합니다. 발송 기록은 새로고침과 백업에도 유지됩니다. 일정 수정·이동은 해당 알림을 재계산하며 업무 완료 시 추가 알림을 보내지 않습니다. 완료 취소 후에는 이후 도래하는 알림부터 다시 적용합니다.

**이번 버전은 앱 실행 중 알림을 확인할 수 있습니다. 앱을 닫은 상태의 예약 알림은 후속 버전에서 지원합니다.** 브라우저 종료나 기기 절전 중 정시 알림을 보장하지 않습니다. 권한 거부·미지원 환경에서도 앱 안의 알림 목록을 사용할 수 있습니다. **1분 뒤 앱 알림 테스트**는 1~2분 후 정각의 일정을 만들어 직접 확인하게 합니다.

`https:`와 `onenote:` 링크만 허용합니다. 원노트의 **단락 링크 복사**로 얻은 원래 주소 전체를 붙여 넣으세요. 주소를 분해하거나 재작성하지 않고 저장·백업·복사합니다. 링크는 사용자가 눌렀을 때만 열립니다. 원노트 설치와 접근 권한에 따라 실행 및 단락 이동이 달라집니다. 예시 데이터에는 가짜 원노트 주소를 넣지 않았습니다.

## 개발 및 검사

React 19 · TypeScript 5.9 · Vite 7. 달력은 자체 구현해 유료 달력 기능이나 API 키가 필요하지 않습니다. 스타일과 아이콘을 포함한 런타임 자원은 로컬 빌드에 포함됩니다.

```powershell
npm ci
npm run build
npm test
npm start
```

개발 중에는 `npm run dev`를 사용할 수 있습니다. 현재 제한된 Windows 실행 환경에서는 Vite 개발 최적화 도구가 상위 폴더 접근 오류를 낼 수 있어 `npm run build` 후 `npm start` 경로로 검증했습니다. 완성본 실행은 이 최적화 과정에 의존하지 않습니다.

- `src/model.ts`: 데이터 모델, 날짜·기간 배치, 검색, 알림 대상 계산
- `src/storage.ts`: 백업 검증, 초기 데이터와 브라우저 저장
- `src/useData.ts`: 저장 오류 처리, 탭 간 변경 수신과 알림 처리
- `src/Calendar.tsx`: 월간 달력, 겹침 처리, 드래그·기간 변경
- `src/Editor.tsx`, `src/Panels.tsx`: 편집, 상세, 백업, 알림 화면
- `src/clay.css`: 첨부 디자인 문서의 색상·글자·모서리·컴포넌트 스타일
- `tests/model.test.ts`: 핵심 날짜·저장·알림·검증 자동 검사

## 범위와 제약

개인용 프로토타입입니다. 로컬 모드는 브라우저 데이터를 삭제하면 JSON 백업 없이는 복구할 수 없습니다. Firebase 모드는 같은 계정의 기기 간 동기화를 지원하며 인터넷 연결과 서버 저장 확인 후 변경을 반영합니다. 동시 수정은 버전을 확인해 오래된 변경을 거부합니다. 다른 사람 초대·공동 편집, 공문 자동 분석, 파일 업로드, 원노트 본문 가져오기와 서버 푸시는 포함하지 않습니다. 클라우드는 원자적 저장을 위해 한 문서를 사용하고 JSON UTF-8 약 900KB를 제한으로 둡니다. 규모가 커지면 문서 분리가 필요합니다. 모바일 드래그는 상세 날짜 편집으로도 처리할 수 있습니다.

검증 내용과 미확인 범위는 `검증결과.md`를 참고하세요. 사용한 패키지의 라이선스 고지는 `THIRD-PARTY-NOTICES.txt`에 포함되어 있습니다.

## Firebase 모드

`.env.example`을 `.env.local`로 복사하고 Firebase 웹 앱 설정 네 값을 입력한 뒤 다시 빌드하세요. Google 로그인 활성화, 승인된 도메인, `firestore.rules`의 본인 UID 설정이 필요합니다. [단계별 연결 안내](DEPLOYMENT.md)를 먼저 확인하세요.

클라우드 계정의 최초 달력은 비어 있습니다. **백업 및 가져오기**에서 기존 JSON 백업을 확인 후 가져오면 같은 계정의 모든 기기에 반영됩니다. 로컬 예시 데이터나 일정을 자동으로 업로드하지 않습니다. 로그아웃하면 달력 화면을 닫고 실시간 구독도 해제합니다. Firebase 웹 SDK의 영구 오프라인 캐시는 사용하지 않습니다.

클라우드 알림 목록과 확인 상태도 공유합니다. 같은 알림을 여러 기기에서 동시에 처리하면 서버 트랜잭션에서 하나만 발송 기록을 저장합니다. 브라우저 팝업은 기록을 저장한 활성 기기에서만 요청하고, 나머지 기기에는 앱 안 목록으로 표시합니다. 서버 예약 알림은 아닙니다.

- `src/firebase.ts`: Firebase SDK, 실시간 구독, 버전 확인 저장, 알림 선점
- `src/useCloudData.ts`: 클라우드 저장 상태·오류·알림 수명 관리
- `src/CloudSession.tsx`: Google 로그인, 계정 정보와 로그아웃
- `src/cloudModel.ts`: 데이터 직렬화, 크기 제한과 충돌 검사
- `tests/cloud.test.ts`: 클라우드 데이터 모델 자동 검사
